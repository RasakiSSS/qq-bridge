日期：2026-10-28。对应 [开发需求 v1.0](UNIFIED_AGENT_REQUIREMENTS.md)。本轮仅修订文档；下列技术验证均未执行，验收编号也不代表测试通过。

后续进展：2026-10-28 已完成首轮现有接口核对与隔离验证，见 [P1 技术报告](UNIFIED_AGENT_P1_REPORT.md)。本清单保留规划时的目标；各项实际证据及尚未验证的内容以报告为准，不能将目标表整体视为已通过。

## 1. 本轮已澄清的规则

| 原有歧义 | 文档结论 |
| --- | --- |
| 主菜单总结是否必须先进入聊天 | 不必。菜单快照、读取回执和总结委托各有范围，都不能充当发送凭证 |
| 一轮结束是否失去峰期当前场景资格 | 不会。等待、休眠和正常回合结束均不等于退出；显式退出、成功切换或资格失效才结束 |
| 峰前取得的其他群快照能否在峰期继续使用 | 不能据此读取、标记隐藏未读或递送总结；结果可保存，恢复资格后再处理 |
| 全局能力是否也必须绑定当前聊天 | 文件和关系操作可从菜单执行；仍校验明确目标、身份、权限及原有工具范围 |
| v3 是否自动开启所有功能 | 不会。首次初始化默认 v3；已保存等级、现有功能开关及部署状态继续有效 |
| 如何证明文件操作是自主决定 | 不做专项证明工程。Agent 根据可信来源和规则判断；程序强制执行身份、权限、工具及路径约束，保留常规行为回归 |
| 单 session 是否意味着删除长期记忆与旧历史 | 不意味着。保留历史和长期记忆；具体复用、迁移与故障恢复方案在 P1 确定 |

参数化工具名、长期记忆保留方式及受控故障换 session 等建议默认设计，仍按主文档的决策记录评审，不写成用户已经逐项明确确认。

## 2. 验证范围与执行顺序

先做当前代码及 DSH 协议的静态核对，再用模拟时间、模拟上游和临时状态验证桥接契约。只有无法由这些证据确定的 DSH 行为，才使用隔离测试 session 验证。禁止把测试事件、已读回执、发布计数或动作结果写入生产状态。

不以修改 QQ 客户端、发送真实好友申请、删除好友或真实群发消息作为 P1 的前置条件。已有能力复用其接口与回归；真实外部动作留到获准的受控试运行。

## 3. 文件自主判断的工作量边界

按用户最新意见，不研发独立意图证明器，不要求每次文件操作另请管理员确认，也不为“完全排除间接影响”反复开展模型实验。

保留的工作是：可信来源记录、权限与路径硬校验、清晰的 Agent 规则，以及少量已有验收场景的常规回归。普通用户明确提出文件要求时应拒绝；真实管理员私聊要求及符合规则的自主操作可执行；转发、延迟或委托不能在规则上改写请求来源。

这部分的语义判断可能受模型误判影响；如实记录即可，不因无法证明内在意图而阻塞工程。程序校验失效、真实身份可伪造或路径越界仍须修复。

## 4. 验证记录与停止条件

每项只记录必要证据：代码/协议位置、测试环境与版本、最小复现、观察到的结果、结论及后续动作。状态使用“未执行 / 已验证 / 采用替代方案 / 阻塞”，没有运行记录就不能写已通过。

关键协议不成立时，先说明具体缺口与最小替代方案，不通过取消校验或重复生产试错推进。涉及改变用户已确认行为的替代方案，需将变更写入需求后讨论；不改变行为的普通实现选择自主解决。

P1 输出只需一份技术结论：实际可用协议、模块划分、状态契约、需要修复的阻塞项、后续实现与验证顺序。自主意图证明不列入阻塞项。此后依次实现基础调度、原能力衔接、迁移与回滚；最终再执行全部验收。

现有峰谷回归中的已知失败见主文档第 12 节，实施时应按真实重试契约处理，不能算作新架构通过结果。本轮文档校验不运行生产桥接或模型调用。
