# 单主会话旧数据迁移方案

本文件说明尚未执行的迁移。`src/unified/migration-plan.js` 只做纯数据试算，始终返回 `dryRun=true, applicable=false`，不提供写入或上线授权。生产统一模式继续关闭。

## 已核实的旧格式

- `social-v2.json` 只有 paused/conversations，没有可靠的机器人账号字段；不能用 ownerQQ、群成员 QQ 或某条消息中的身份来推断归属。
- 每个场景保存 recentMessages、unread、lastUnreadSeq、lastReadThroughSeq 和 wakeConfig。落盘的 recent 最多 200 条、unread 最多 100 条；配置中的运行时容量不能补回早已被丢弃的记录。
- 入站 text/plain 已截断为 200 字左右，另有尾部预览、媒体和转发引用。拼接首尾不等于恢复原文。迁移计划将旧消息统一标记 originalUnavailable，不能作为完整原文阅读回执的证据。
- lastUnreadSeq 是场景内部序号，不能直接写入新 SQLite 的全局 seq。每条需要独立映射。
- recent 中没有出现在 unread 的消息，只有在已确认水位内或确为自己发送时才能视为已读；其他记录保持 unknown，不能把容量淘汰当作确认。
- Qzone 按机器人账号保存 ownPosts、seenFeeds、pendingFeeds、comments、commentCursors 和 writes。空间已读与评论已读必须分别处理，自己发布的动态不代表评论已读。

## 执行前的必要条件

1. 在受控维护窗口暂停旧模型调度并确认所有旧 DSH 会话无运行/排队工作。收件继续可靠保存，不能因暂停而丢消息。当前开发轮不执行该步骤。
2. 核验当前 OneBot 登录账号和连接代次。取得独占安装锁，在旧状态写入与接收队列的协调点采集快照；采集前后账号、代次和文件指纹一致。单纯复制正在被写的 JSON 不构成有效快照。
3. 将旧状态、会话映射、唤醒偏好、初始提示词、角色选择、空间状态及配置快照保存到模型无法读取的私有备份目录，记录原始字节哈希、时间、版本和可信账号。共同记忆 SQLite 用一致性备份接口，不能只复制正在使用 WAL 的主文件。
4. 不把旧 agentToken、绑定文件、API 凭据或整份快照写入迁移报告、工具结果或远端仓库。只给操作员展示计数和冲突；新主凭据仍重新按原 ACL 流程签发。

## 导入规则（隔离账本写入已实现，生产切换尚未接通）

- 新建独立迁移台账，记录 snapshotId、账号、版本、每条来源标识与新 seq；整批变更在一个事务内提交。重复提交同一快照无副作用；不同快照不能覆盖已投入使用的统一账本。
- 有可信 messageId 时与统一收件箱实际入站 ID 对账。同一 ID 或旧 seq 对应不同内容即阻断，不选择较新的一份。没有 messageId 的记录使用快照、场景、旧 seq 派生的稳定来源 ID。
- 原 unread 集合逐条保留，不通过最高 seq 批量确认；预览只能显式略过，或取得可信原文后再发完整读取回执。unknown 的旧记录单独列入迁移审阅，不偷偷归为已读或触发一轮群发。
- 原媒体、转发引用另存受限历史来源；目前试算器只投影文本和身份摘要，不能直接当作完整导入数据。
- wakeConfig 保留潜水、关键词、概率和无限睡眠偏好。有限睡眠保留绝对 sleepUntil，不从迁移时刻重新计时。过期提醒最多生成一次，用稳定来源 ID 去重；仍受峰谷和人工暂停限制。
- 旧主动机会、回复检查和 pendingThoughts 与新关注项协调后才能恢复；禁止既导入提醒又让旧定时器继续运行。试算只标记有限睡眠和局部记忆待映射，不声称已迁移全部任务。
- 旧 DSH session ID 只作历史索引，不挪动、归档或删除。不得将旧消息全量塞入主 session。已有 memory.sqlite 继续原位使用，局部事实必须匹配原始证据后再整合。
- 空间先按账号与动态/评论稳定键映射 pending 和 seen。确认过的旧空间依据映射到统一已读记录，解决峰期保守隐藏；未知发送仍保持 unknown，不重发。
- 角色卡直接复用原文件；统一预设的权限/工具协议不被旧逐聊天预设整段覆盖。旧自定义仿真正文需要显式评审适配，不能自动混入包含旧 token/路由要求的指令。

## 回滚及验收

切换前对隔离副本演练：重复导入、导入中断、账号变化、原文不足、冲突 ID、峰期、人工暂停、过期定时器和空间评论。对账每个来源集合，不仅比较总数。

回滚不覆盖已经新增消息的原文件。必须先停止新模型调度、保留新账本和动作未知项，将切换后新入站按稳定 ID 合并回旧收件路径；旧原件加增量共同恢复。对于已发送/未知动作不得重放。模型工作仍在途或来源无法对账时，保持暂停并要求操作员核查。

只有完成快照采集器、事务导入器、空间映射、增量回退和真实隔离启动验证后才能考虑启用生产统一模式。本轮测试全部使用合成数据，没有执行生产迁移。


## 2026-10-30 隔离实现状态

目前可执行的开发模块（均未接到生产控制台或启动流程）：

1. `migration-snapshot.js` 提供固定文件映射读取、`captureMigrationSnapshot` 和验证加载器。源清单覆盖 QQ/空间状态与旧会话索引、初始提示词、模式、配置、角色及各代预设。文件缺失也记录在摘要中；副本提交前二次读取并核对。宿主必须提供独占、停稳、持久收件的 lease，账号、连接代次、来源账号及可信归属凭据都需要一致。只有当前登录账号不足以证明旧文件归属。生产 lease/账号归属证明适配器尚未接通。
2. 快照存放目录必须由宿主验证操作系统权限和模型文件根排除；禁止符号链接、junction 和硬链接，拒绝未知文件路径。SQLite 使用 Node backup API 读取一致副本，包含 WAL 已提交内容，校验分块处理大库。完整文件内容只保存在私有快照，不进入日志。manifest 作为完成标记；失败留下不可导入的部分副本，不清理原件。
3. `migration-stage.js` 把已验证快照事务写入独立暂存 SQLite（独立 application_id，绝不是运行账本）。保留精确来源、媒体/转发引用、局部记忆、唤醒偏好、旧 session 索引和当前账号的空间原始状态。旧 agentToken 与配置密钥不复制到暂存查询表；配置原件只在私有快照中。不同快照不能覆盖同账号已暂存批次。旧空间 read/seen/comments 原样保留，但尚未投影为统一空间回执。
4. `migration-import.js` 只能向空的 UnifiedStore 写入同一批次，需宿主独占断言，整个过程原子提交。schema 6 增加批次、来源映射和待整合资料表。明确 read/unread 的 QQ 记录映射到新 seq；unknown 留在来源表待核对，不猜成已读或未读。旧预览标记 originalUnavailable，不导入旧 DSH session 绑定，不启动主会话。有限睡眠保留绝对截止时间，入站 wake 默认关闭。手动暂停原值保存在批次，新账本强制暂停且 phase=staged。
5. `UnifiedScenes.active` 的迁移锁独立于人工暂停；即使清除 paused，仍会报 MIGRATION_PENDING，阻止模型、工具和定时唤醒。控制台显示“待迁移验收”。**尚无解除迁移锁或生产激活入口**，不得直接改 SQL 绕过。
6. 预览读取回执排除不完整来源；响应返回 incompleteSeqs 和额外精确 skipReceipt，只有明确略过才确认这些旧消息。总结入口和完成保存都拒绝不完整原文。已存在的完整消息不受影响。
7. 暂存库支持增量输入及动作结果保留；回滚计划以一致事务快照生成，保留新增输入，列出未知动作和与旧 ID 的冲突，不重放发送。它始终 `applicable=false`：真正的旧状态合并写入、已读变化反向映射、在线增量采集和停稳切换仍待实现。

已经测试进程在提交前退出、异常回滚、重复/冲突快照、账号不符、源采集中变化、WAL、媒体冲突、未知已读、暂停锁和过期定时器不触发。尚未在生产路径采集任何快照、创建迁移数据库或执行回退；真实 Windows ACL 与生产协调 lease 仍需单独验收。

## 2026-10-31 空间隔离投影补充

隔离导入现在调用 migration-qzone.js，按原稳定键分别映射动态及评论。自己的动态已读不传播到评论；replied 发送意图不当成成功，只有对应 sent 回复证据可确认。historical、非关注新评论、无来源时间等情况保留来源供审核。seen 中仅剩键而无正文的不创建虚构内容。所有旧内容仍标记不完整；事件不触发唤醒，迁移锁仍在。

空间映射与 QQ 导入同事务，任何冲突回滚整个目标导入。原始空间分区（包括游标、发送状态）继续保留，反向回滚仍未实现。空间来源 legacy_seq=0 仅表示不适用 QQ 序号。已经导入的旧隔离目标不自动升级或重置；同快照仍幂等，需要后续显式对账。

持续收件适配尚未接通：现有 stage.delta_events 依赖已建立 batches，无法承担快照前收件，应先建立独立持久日志和停稳屏障。真实账号归属、独占锁和操作系统权限仍须验证。

## 2026-10-31 收件屏障及增量导入补充

独立 migration-ingress 日志现可在快照前持久保存入站；日志身份绑定账号、epoch、归属证明，冲突副本也保留。createMigrationBarrier 等待经它登记的旧工作，核验旧 DSH 空闲并 flush 后提供快照 lease；释放 lease 不解除持久收件屏障。**还未接入生产 bridge 的所有收件、写入、调度入口**，真实独占及权限仍待验证，不能直接作为线上停稳证明。

日志到 stage 转移采用目标先提交、源进度后提交，允许崩溃后稳定 ID 去重重试；每次核对目标已有前缀，避免换库丢消息。增量再通过 migration-delta 原子写入 paused/staged 统一目标。基础快照导入可显式 retainDeltas=true，但这不表示增量已对账或允许激活。旧预览 ID 重叠始终要求原文恢复，不自动覆盖；动作未知项仅归档、不重试。好友申请的增量投影尚未支持。没有清屏障、改 ready 或恢复旧调度的入口。

回滚合并写入、读状态反向映射、真实桥接接线和激活验收仍未完成。日志的 sourceId/时间/完整正文必须来自可信收件适配，不能由模型或当前时间重建。所有新验证使用临时夹具，不操作生产数据。

## 2026-10-31 维护期限补充

停稳 acquire 已增加默认30秒、最大60秒的总期限，使用单调时钟。超时后仍持久收件，不清 barrier；迟到的 idle/flush 回调仍跟踪，重试先等待其结束，避免假停稳。它不能取消外部正在进行的写入。完整相关回归370项通过。

生产接线前的具体入口和风险已记录在 IMPLEMENTATION 最新交接：handleIncoming 在首个 await 前写共同记忆，saveSocialV2State 吞掉保存失败，好友申请/拍一拍/DSH回帧/控制台/端点自愈及后台任务均需单独纳入协调。不能用 DSH 空闲或单独 prompt guard 代替全部源状态停稳。

## 2026-10-31 严格保存接口补充

实际桥接的 sessions、social-v2 和 initial-prompts 保存函数增加宿主 strict:true 选项。严格模式要求临时文件fsync、原子替换和完整目标读回核验；失败或只读降级抛错。损坏/未验证加载的二代源不得严格保存为默认内存态。默认旧调用行为保留，未开放生产维护路由。

这只解决组合flush所需的部分保存原语，不代表所有源状态已冻结，也不证明源账号归属。原件备份、空间及其他源写入协调、真实独占/ACL和Windows持久性验收仍必须完成。374项完整回归、26项旧安全回归及加固检查通过，全部使用隔离夹具。
