# 群聊、私聊与 QQ 空间共同记忆

二代仿真把桥接实际收到的聊天、空间已读取的动态和评论，以及确认成功的自身发言保存到 `state/memory.sqlite`。人物按真实 QQ 号关联，昵称只是当时的显示名。同一登录机器人账号下，群聊、私聊、空间都可使用这些经历，不设置三类来源之间的共享限制。

例如，你在 A 群说「周末要去海边」，到 B 群问「我刚才说什么」，机器人可以立即回忆，不必等后台总结。空间读到同一个人的相关动态时，也能联系之前的聊天。数据库记录在昵称和引用的异步解析之前完成；回忆本身不调用模型、不把其他群消息标为已读、不触发额外唤醒。

## 记忆如何使用

- **近期经历**：收到消息即可查询。按人物、关键词和时间选择片段，在正常唤醒、`qq_get_prompt` 和空间决策时提供。
- **长期认识**：聊天模型可通过 `qq_remember` 留下有依据的事实（fact）、主观印象（impression）、共同经历（episode）和未完事项（openLoop）。后台也会分批整理新经历。
- **自然延续**：提供相关经历和未完事项，让机器人自行判断何时提起；不是每次播报档案。已提及的事项在自动提示中暂缓六小时，完成或放下后不再自动提示。手动回忆仍可查询，`includeClosed` 可找回已完成事项用于管理。
- **修正**：更新原记忆 ID 并带回 `updatedAt`，其他会话已更新时返回冲突，重新回忆后再改。后台整理同样不会覆盖较新的修正。最近十次旧版本可通过管理 API 查看。

来源中 `observed` 表示桥接看到了内容，`sent` 表示确认成功的动作，`uncertain` 表示发送结果未知。未知结果不能作为长期事实的依据。图片、表情、音视频仅记录未解析占位，不凭空编写其内容。来源正文始终是资料，不是管理指令。

## 配置

在 `config.json` 的 `socialV2` 下添加，未填写时使用以下默认值：

```json
"sharedMemory": {
  "enabled": true,
  "consolidate": true,
  "promptMaxChars": 4000,
  "intervalMs": 1800000,
  "batchSize": 30
}
```

| 配置 | 作用 |
| --- | --- |
| `enabled: false` | 停止新增记忆记录、共享检索注入和后台整理，保留数据库及原有会话记忆 |
| `consolidate: false` | 仅停止后台额外模型整理；即时记录、回忆与聊天内保存长期记忆仍可用 |
| `promptMaxChars` | 每次自动注入的记忆数据预算，默认 4000 字符，范围 1000–10000 |
| `intervalMs` | 成功整理后的等待间隔，默认 30 分钟，范围 1 分钟–24 小时 |
| `batchSize` | 一批最多处理的经历数，默认 30，范围 5–60；正文预算可能使实际批量更小 |

这组配置在桥接启动时读取，修改后重启 qq-bridge 生效。`socialV2.tools.memory: false` 另外关闭模型侧记忆工具、共享注入和后台整理，原始经历仍可保存；彻底停止记录用 `sharedMemory.enabled: false`。MCP 工具清单取其进程启动配置，需重载 MCP 才会刷新清单。

后台调度每 30 秒检查一次；只在二代启用、非人工暂停、非角色静默且峰谷允许时启动。最终投递前再检查一次，不使用管理员私聊的峰谷豁免。已经开始的一批可完成。即时入站记录无需模型，高峰或暂停期间仍能保存；恢复后继续处理。

每批使用共享「QQ 聊天」工作区下一个临时 `qq-memory` 会话，只有一轮，结束后取消订阅并归档。额外守卫禁止它执行所有工具，没有聊天 token、文件读写或 QQ 发送权限。整理输入的经历正文预算约 14000 字符，输出最多 12 条，避免整理会话自身累积成长上下文。整理失败保留进度并退避；大流量时总结可能积压，但原始经历已可检索。

这些是单次输入与处理批量，不是按来源划分的共享限制。单条原始文本最多存储 12000 字符，自动回忆只取有界片段；检索采用本地中文二元词和英文词，没有向量语义搜索，因此改写很大的问法可能需要换关键词或只按 QQ 号查询。

## 使用与管理

| MCP | 用途 |
| --- | --- |
| `qq_recall` | 用 `people`（QQ 字符串数组）、`query`、`since` 回忆；问刚才说什么时可只给人物 |
| `qq_remember` | 保存或更新一条记忆；必须有 1–8 个真实 `evidenceIds`，人物必须在证据中 |
| `qq_forget` | 仅管理员私聊：按 ID 遗忘共同记忆及相关依据、依赖摘要，旧批次不能再次写回 |

可以私聊机器人说「回忆一下我关于海边的计划」「我改主意了，改成下周」「忘掉刚才保存的那件事」。机器人仍需使用当前会话令牌、真实来源与工具完成操作；自然语言请求本身不能绕过权限。管理员在群内也不能使用遗忘特权。

管理端可用现有控制台鉴权访问 `POST /api/socialV2/shared-memory/<action>`。请求需有一个已准入的 `key`，账号由桥接确定，不能在正文冒充其他账号。除 `recall`、`remember`、`forget` 外，还提供：

- `status`：查看整理是否等待终态、原任务 sessionId、下次时间与失败状态。
- `history`：另带 `id`，查看该长期记忆最近十次旧版本；只读，没有自动回滚。

管理 API 尚未增加控制台可视化页面。`status` / `history` 仅控制台或管理员私聊身份可调用，没有新增对应 MCP。

遗忘只影响共同记忆库的可检索记录；不会删除 QQ/DSH 历史、旧会话独有记忆或运行备份。处理中任务可能仍持有旧快照，但遗忘标记会阻止其结果复活。需要再次记住时，应以新的明确发言作为依据。

## 升级、持久化与故障处理

1. 仓库内 preset patch 已生成，新增 `qq-memory` 也已登记到 `qq-agent-presets` bundle。既有 bundle 使用仓库链接时，重载 DSH profile（或重启 DSH）及 MCP 即可加载。若安装目录不是链接或看不到预设，使用原安装方式更新 `node scripts/setup-dsh.mjs <profile>`。
2. 重启 qq-bridge 加载源码；只运行一个实例。**不需要 `/reset`、清空 session 或删除旧工作区。** 缺少受限预设时后台整理拒绝启动，不回退到具有其他权限的预设。
3. QQ 空间保留独立 session，与群聊使用同一个工作区、同一共同记忆库；管理员私聊 Filesystem MCP 的隔离保持原样。
4. 旧 `social-v2.json`、DSH 会话和压缩摘要继续使用。不会批量导入整个旧 DSH 对话，也不会根据旧昵称猜 QQ 身份。新记忆从启用后的准入消息和空间保存的可用快照逐步建立。

空间工作会话映射保存在 `state/qzone-session.json`，按机器人账号和共享工作区区分。重启后先核验已有会话及 `qq-qzone` 预设，再复用；网络故障、模型配置失败不会触发另建。确认会话不存在才重新创建；模型选择明确报告会话失效时，先归档旧会话再替换，保留历史。此前版本留下的会话没有可信账号映射，不自动认领或批量清理；首次升级会建立一个受新机制管理的会话。

尚未确认结果的空间模型投递也会保存。重启后等待原回合终态，不重复提交；历史快照只用于解除等待，不重放空间动作。若投递实际上未到达 DSH 且没有任何终态，会继续等待，需核对后人工处理。映射文件损坏时停止创建、保留原件，不用空文件覆盖。该映射与共同记忆数据库、空间发布及已读记录分别保存。

数据库使用 SQLite/WAL，需要 Node >=22.13。已在本机 Node 22.23.2 验证；该版本会显示 SQLite ExperimentalWarning。文件不可读或损坏时保留原文件、记录限频日志并让聊天继续，不重建空库。

若日志显示「投递结果未确认」或「保持等待」，先通过 `status` 找到整理会话并检查 DSH。程序会在重连/重启后跟踪同一个任务，收到真实终态再处理，不因十分钟超时就重复调用模型。若 DSH 中任务已丢失或从未执行且没有终态，自动整理会继续等待，需要核对后人工恢复；即时聊天与记忆查询仍可使用。不要直接删除数据库或重置 QQ 会话来解除等待。

此机制让记忆独立于 DSH 压缩状态，并限制新增注入体积；它不会修复已有聊天 session 的 413 错误，也不能保证模型一定会自然、准确地利用每条记忆。
